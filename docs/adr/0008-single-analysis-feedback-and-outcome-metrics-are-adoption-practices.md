# 維持單次分析：驗證回饋與成果型指標由導入的組織建立，不在技能裡計算

2026-10-30 的全 repo 審查（#168）拿 CTEM 五階段對照八步流程，指出兩個缺口：
- 驗證之後沒有回饋。S6 只產出驗證計畫，流程裡沒有「驗證結果回來之後，重評 S3、修正 S5」的步驟。
- 追蹤指標（O6）只有數量與資料品質，沒有成果型指標，例如關鍵曝險的修補時間、改善結案率、驗證結果為 `validated-blocked` 的比例。

這兩件事都需要跨期的資料：上一輪的輸出、修補或工單的歷史、驗證結果。現有輸入只有單次的快照。

決定（維護者，2026-11-05）：

- **維持單次分析。** 不新增跨期輸入，八步流程不變，O6 仍只輸出當期數值。
- **驗證回饋寫成導入時應建立的制度。** 授權驗證完成之後，由人回填路徑狀態與授權證據（輸出 schema 已有 `validated-feasible`／`validated-blocked` 與 `evidence`）。下一輪分析把回填結果當成輸入的一部分，據以重評相關發現、修正或撤回改善建議，並評估改善方案的效果與組織上的可行性。
- **成果型指標也寫成導入時應建立的制度。** 至少有三項：關鍵曝險的修補時間（time-to-remediate）、改善結案率、驗證結果為 `validated-blocked` 的比例。每一項依賴哪些跨期資料，寫在研究文件第 3 章 3.6。
- 這兩件事的說明都放在研究文件第 3 章 3.6「已實作的能力與導入時應建立的制度」，標為本專案推論。S8 與 O6 的依據段改成指向 3.6 與本 ADR。

## Considered Options

- **新增跨期輸入（上一輪的輸出 JSON、修補紀錄、驗證結果），讓技能算出成果指標：** 否決。會改到輸入 schema、任務規格、核心提示詞（模型讀的文字，CODING_STANDARDS §3）、示範引擎、合成資料與驗收。影響很大，而且單次分析的使用情境用不到這些輸入。
- **新增第九步，或在八步裡加「S6 的結果 → 重評 S3、修正 S5」的迴圈：** 否決。理由同上。此外，一次分析之內拿不到驗證結果：技能不執行驗證，驗證要由人取得授權後另外進行，迴圈在單次分析裡永遠不會被觸發。
- **只在 S8 加一行「下次分析要帶入的驗證結果」：** 不採用。這樣會讓單次分析的輸出看起來像有跨期功能。改為在 3.6 寫明制度怎麼運作，輸出保持不變。

## Consequences

- 技能的輸入、輸出、模型讀的文字、示範引擎都不變。驗收與示範快照的預期也不變。
- 輸出 schema 的 `validated-*` 狀態與 `evidence` 欄位繼續作為回填的位置，但技能本身不會產生 `validated-*`，除非使用者提供已授權的驗證結果。
- 成果型指標要由導入的組織，用自己的發現登錄冊、結案證據與驗證回填紀錄來計算。研究文件不宣稱本專案已經對齊 Gartner 的「time-to-remediate」建議。
- 「資料齊備程度」的四個面向（資料新鮮度、來源可信度、實證驗證狀態）留到之後（#152）。驗證回饋將來如果要進到技能裡，會和「實證驗證狀態」一起設計：兩者需要同一份驗證結果的資料來源。
- 「validation 也評估改善方案的效果與組織上的可行性」是本專案推論。研究文件沒有附來源 ID 的原文支持，所以不掛在 Gartner 或 CTEM 名下。
