# API 路徑由腳本先算出曝險分數，模型只負責解讀

曝險分數（likelihood、impact、score、priority、factors）原本全部交給模型照規則計算。Gemini 真實模型驗收（#153、#209，紀錄見 `docs/evidence/model-acceptance-gemini-2026-11-06.md`）顯示這樣不可靠：

- 模型照抄了 `meta.scoring_rules` 的公式，算出來卻和公式對不上。例如 EASM 按項數加分（公式是有無判斷），也多算了不存在的控制缺口。
- 同樣的程式碼和輸入，跟示範引擎（`assets/demo.js`）的分級一致程度：第 1 次 6/14、第 3 次 13/14、第 4 次 7/14。即使某一次看起來很準，也不是穩定的結果。
- 驗收的「輸出內容一致」（0e）只驗證 `score = likelihood × impact` 和分級門檻，不驗證分數是否照規則從輸入算出，所以這類錯誤不會被機器檢查抓到。

決定（#208，A 案）：

- **API 路徑由腳本先算出分數。** 五支 `api-workflow.py` 在送出前，依示範規則算出每一項發現的 likelihood、impact、score、priority 與 factors，以結構化區塊放進第 1 段的提示詞。模型照用這些數字，負責排序說明、改善建議與管理摘要，不重新計算。
- **模型照用的程度由程式檢查。** 第 2 段的 JSON 輸出中，`exposure_priorities` 的 priority 與 score 跟腳本算出的不一致時，視為輸出不合格（比照內容一致性檢查，結束碼 4）。
- **規則數值的唯一來源不變**，仍是示範引擎的 `RULES`（`scoring-rules.mjs` 的一致性檢查照舊比對母本散文）。Python 讀的規則數值由建置從 `RULES` 產生，提交進 git（比照 ADR 0001），Python 不另外寫一份數值。
- **算法有兩份實作**：示範引擎的 `analyze()` 與 Python 分析工作流程核心的新函式。這是同一條規則的兩份實作，由共用案例（輸入與預期分數）守住一致，合成資料另外比對示範快照 `examples/demo-snapshot.txt`（比照 ADR 0004、ADR 0007 的做法）。
- **對話介面路徑維持模型自己算**（ChatGPT Project、Custom GPT、claude.ai、Gemini 應用等）。這些路徑沒有腳本可以先算，核心提示詞照舊寫明評分規則。
- **風險胃納**：API 路徑沒有示範頁的胃納選項，一律用預設的平衡胃納（示範引擎 `DEFAULTS.riskAppetite`）。
- **範圍**：這份決定先處理曝險分數與分級。攻擊路徑假設（含可行性）也由腳本產生的做法另外決定；它能一併解決路徑與拓樸不一致的問題（#220），但改動更大。

## Considered Options

- **B 案：維持模型計算，驗收新增「依合成資料重算分級並比對」的判定。** 否決。這樣只能讓不一致在驗收時以不通過的形式出現；使用者實際執行時拿到的分數照樣不穩定，管理摘要的 P1 數量也會跟著變動。
- **Python 腳本呼叫 Node 執行示範引擎。** 否決。API 腳本與 Claude、Gemini 的技能資料夾只要求 Python 標準函式庫（ADR 0003），不能多一個 Node 執行環境的依賴。
- **把規則數值改寫成 JSON 母本，示範引擎與 Python 都讀它。** 否決。網站要能從 `file://` 直接開，示範引擎在瀏覽器裡讀不到另外的檔案；`RULES` 目前就是唯一的可讀來源，改由建置從它產生 Python 用的資料，影響最小。
- **只把公式寫得更清楚、給模型範例。** 否決。#205 之後模型已經拿到完整公式與 schema，第 3、4 次執行的差異來自計算本身，不是規格描述不清楚。

## Consequences

- **核心提示詞要改**（模型讀的文字，所有走 API 腳本的平臺都受影響）：提示詞裡有預先計算的分數時，照用、不重新計算，並在 `meta.scoring_rules` 說明分數由腳本依示範規則算出。對話介面路徑的規則描述不變。
- Python 核心多一份評分實作，要跟示範引擎一起維護。規則數值改了只要改 `RULES`；算法改了兩份都要改，共用案例會在只改一份時失敗。
- 輸出的分數與分級在 API 路徑上會穩定下來，驗收第 2 項與示範引擎的對照，也不再隨執行而變動。管理摘要裡的 P1 數量等內容仍由模型撰寫。
- 網站的「AI 分析」經後端代理送出時，也可以附上示範引擎算好的分數（JS 現成就有），作法與 Python 路徑相同，另外實作。後端代理收到回應後也檢查模型輸出跟分數表是否一致，不一致時回 502（#247），規則跟 Python 路徑相同，由共用案例守住。
- 驗收紀錄範本的「與示範引擎的對照」一節，在 API 路徑上會變成檢查「模型有沒有照用」，而不是「模型算得準不準」。
